# CLAUDE.md

Guidance for Claude Code (claude.ai/code) when working in this repository.

## What this is

A static Astro 7 site for the **Innopolis Chip Design Club**, built on the
[AstroWind](https://github.com/arthelokyo/astrowind) template (MIT). No CMS, no database, no
backend, no hosting-provider binding.

**One build serves two zones**: a portal at `/` and the club site under `/club`.

**`CLUB.md` is the source of truth for every club fact** — names, domains, contacts, the join
framing, and the list of things still unconfirmed. Read it before writing user-facing copy. If you
find yourself typing an address, a Telegram handle or a founding year into a `.astro` file, it
belongs in `src/data/site.ts`, which is generated by hand from `CLUB.md`.

## Commands

```bash
pnpm install
pnpm dev                                    # http://localhost:4321
pnpm check                                  # astro check + eslint + prettier
SITE_URL=http://localhost:4321 pnpm build   # requires SITE_URL
pnpm preview
pnpm fix                                    # eslint --fix + prettier -w
pnpm icons                                  # regenerate the favicon set from src/assets/logo.svg
```

Node ≥ 22.22.3, pnpm 10 (pinned via `packageManager`).

### `SITE_URL`

Canonicals, the sitemap and OG image URLs are baked in at build time, so the origin has to be
settable per build. `SITE_URL` overrides `site.site` in `src/config.yaml`; the override lives in
`vendor/integration/utils/configBuilder.ts` (a **local patch** to otherwise-vendored upstream code)
because setting `site` in `astro.config.ts` does not work — the integration calls
`updateConfig({ site })` during `astro:config:setup` and overwrites it.

The dangerous failure is not a crash but a wrong-but-valid origin: it ships wrong canonicals and
wrong link previews while nothing looks broken locally. 🔴 The canonical domain is still undecided —
see `CLUB.md` §2.

## Architecture

### Two zones, one build

There is no Astro `base`. `/club` is a real directory under `src/pages/club/`. Three layouts:

- `Layout.astro` — the base document: head, tokens, theme script. Shared by both zones.
- `PageLayout.astro` — the **club** layout: header with the club nav and a portal link, footer.
- `PortalLayout.astro` — the **portal** layout: no header, no footer, no nav.

**The portal is a switchboard, not a page.** If `/` ever grows a projects section or an about
paragraph it has become a homepage and the `/club` split has lost its point.

### Data

No content collections yet. `src/content.config.ts` keeps `metadataDefinition()` as the seed for the
projects and events collections, which are the next thing this site grows.

- `src/data/site.ts` — every club fact. Generated by hand from `CLUB.md`.
- `src/data/services.ts` — the club's web properties. Drives the portal tiles at `/`, so adding a
  property is a one-file change. The club header deliberately carries **no** service buttons: under
  `/club` the route to the other properties is the portal link beside the wordmark.

## Design system — "Light, bright & academic"

Light default, generous whitespace, serif headings over a sans body. Dark mode is a toggle, not a
default (`ui.theme: 'light'` in `src/config.yaml` — **not** `'system'`, which would hand dark mode to
every visitor whose OS prefers it).

### The token bridge

Two layers, and the split matters:

| Layer       | Where                                     | What                                                  |
| ----------- | ----------------------------------------- | ----------------------------------------------------- |
| `--club-*`  | `src/components/CustomStyles.astro`       | the palette. **The only place a raw hex may appear.** |
| `--aw-*`    | same file                                 | AstroWind's variables, aliased onto the tokens above  |
| `--color-*` | `src/assets/styles/tailwind.css` `@theme` | Tailwind utilities, pointing at `--aw-*`              |

Every widget in the template reads `--aw-*`, so the whole theme follows from `CustomStyles.astro`.

**Club tokens are named `--club-*`, never `--color-*`.** `tailwind.css` already declares
`--color-accent: var(--aw-color-accent)`; naming ours the same makes the two reference each other
and resolve to nothing.

Because the aliases are `var()` chains, `.dark` redefines only `--club-*`. That buys the rule for
free: **no colour is ever defined only inside `.dark`**, so a missed token can never render as
transparent or black-on-black.

Use plain `@theme`, never `@theme inline` — inline bakes the literal in and silently breaks dark mode.

### The green is brand-only

`--club-brand: #40ba21` is the mark's green. It is **2.2:1 on white and fails WCAG AA.** Darkening it
far enough to pass (≈ `#1B6410`) is no longer the club's green. So the interactive accent is **blue**
(`#1d4ed8` light, `#6e9bff` dark) and the green is used only where the colour carries no information
a screen reader would miss — the mark itself. Never a link, a button, a focus ring, or
`--aw-color-primary`.

### Type

Source Serif 4 (headings) · Inter (body) · JetBrains Mono. Self-hosted through the Fonts API's
`local` provider against installed `@fontsource-variable/*` packages — **not** the remote
`fontsource`/`google` providers, so the build works on a machine that cannot reach the internet and
no font binaries enter git history.

The serif is for headings only. Serif body text at screen sizes is the classic way an "academic"
design becomes an unreadable one.

Contrast pairs, all WCAG AA or better — recheck whenever a token changes:

| Pair                  | Light  | Dark   |
| --------------------- | ------ | ------ |
| text on bg            | 16.8:1 | 15.1:1 |
| muted on bg           | 5.9:1  | 6.4:1  |
| accent on bg          | 7.5:1  | 6.2:1  |
| bg on accent (button) | 7.5:1  | 8.9:1  |

## House rules

- **No club fact hardcoded in a component.** It goes in `src/data/site.ts`.
- **No raw hex outside `CustomStyles.astro`.** If you need a colour that is not a token, add a token.
- **Tailwind v4 is a Vite plugin**, not an Astro integration.
- **Internal links go through `getPermalink()`** (`src/utils/permalinks.ts`), never string
  concatenation. `trailingSlash` is `'never'`, set in `src/config.yaml` and **only** there — setting
  it in `astro.config.ts` too makes the two fight.
- **Zero third-party requests.** No analytics, no remote fonts, no map embed, no CDN. That is why
  there is no cookie banner. It is much easier to keep than to win back — check the diff before
  adding anything that loads from another origin.
- 🔴 markers in code flag facts the club still owes us. `grep -rn "🔴" src/` lists them; they are
  tracked in `CLUB.md` §7.

## Gotchas

These are all things that fail _quietly_.

- **Do not delete `Intersect.astro`.** Every `WidgetWrapper` carries
  `motion-safe:md:opacity-0 motion-safe:md:intersect:animate-fade` — sections start invisible above
  `md` and are revealed by that observer. Removing it renders the site **blank on desktop and fine on
  mobile**. If you strip the observer, strip those classes in the same commit.
- **`Content.astro` always renders its image column**, `aria-hidden` and 50% wide. With no `image`
  prop you get an empty half and lopsided text. Use plain prose markup instead when there is no image.
- **`Hero`/`HeroText` open with `md:-mt-[76px]`** to slide under the sticky header. On a page without
  one — the portal — that pulls content off the top of the viewport. The portal uses no widgets.
- **Icons are Tabler, with one exception.** `flat-color-icons` was dropped with the demo pages. The
  header's portal link uses `lucide:arrow-up-left`, and `astro.config.ts` allowlists exactly that one
  name — adding another `lucide:*` icon fails the build until it is listed there too.
- **`astro-compress` keeps `csso: false` on purpose.** csso's parser does not understand the media
  range syntax Tailwind v4 emits (`@media (width>=48rem)`) and silently drops every one of those
  blocks — the site then renders as if all `md:`/`lg:` classes were missing.
- **`~/` is aliased twice and needs both**: `tsconfig.json` `paths` for the editor and `astro check`,
  `astro.config.ts` `vite.resolve.alias` for the bundler. Drop either and you get a green typecheck
  with a broken build, or the reverse.

## Divergence from upstream AstroWind

Worth knowing when pulling anything from upstream:

- the blog, and every widget serving it, is deleted (`apps.blog.isEnabled: false` as well);
- `Announcement`, `Contact`/`Form`, `Testimonials`, `Pricing`, `Brands`, `Hero2`, `Features3`,
  `Steps2` and `Analytics` are deleted;
- `vendor/integration/utils/configBuilder.ts` is patched for `SITE_URL`;
- `Header.astro` gained a `homeHref` prop so the club zone's wordmark links to `/club`, not `/`;
- `Favicons.astro` reads the root-absolute set from `public/` and emits the web manifest, which
  upstream never does;
- the ~67 hardcoded `dark:*-slate-*` / `dark:*-gray-*` classes in the kept widgets were replaced with
  tokens. Re-introducing one puts a Tailwind grey next to a club colour in dark mode.
